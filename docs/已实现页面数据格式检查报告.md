## 二、届次管理（`AcademicYear.vue` / `YearFormDialog.vue` / `api/academic.js` / `mock/_shared.js` / `mock/academic.js`）

文档契约（`GET/POST/PUT /api/academic-years/`）字段：**`id` `name` `start_date`(string) `end_date`(string) `status`(enum) `is_current`(bool)**，列表为数组响应。

### 🔴 A1 列表渲染字段与文档不符
- `src/views/admin/AcademicYear.vue` 第 147 行 `{{ y.start_year }} – {{ y.end_year }}`、第 148 行 `{{ y.created_at }}`。
- 文档无 `start_year`/`end_year`/`created_at`；对应应为 `start_date`/`end_date`（日期字符串，如 `2026-09-01`）。
- **修正**：改读 `y.start_date`/`y.end_date`；「创建时间」列文档并无对应字段，建议删除该列（或仅作前端展示、明确标注非后端字段）。

### 🔴 A2 提交字段名全错（create/update）
- `src/components/admin/YearFormDialog.vue` 第 14、50-55 行提交 `{ name, start_year, end_year, set_current }`；`api/academic.js` 注释写「body 可含 set_current」；`mock/_shared.js` 的 `addYear/updateYear` 也用 `set_current`/`start_year`/`end_year`。
- 文档创建/更新请求体为 `{ name, start_date, end_date, status, is_current }`。
- **修正**：`set_current` → `is_current`(boolean)；`start_year`/`end_year`(number) → `start_date`/`end_date`(日期字符串)。

### 🟡 A3 创建时未传必填 `status`
- 文档 `status` 为必填枚举 `DRAFT/PREPARING/IN_PROGRESS/FINISHED/ARCHIVED`；前端提交不带 `status`。
- **修正**：新增时默认 `status: 'DRAFT'`（或按需），编辑时保持原值。

### 🟡 A4 Mock 初始/返回数据字段错
- `mock/academic.js` + `mock/_shared.js` 用 `start_year/end_year/created_at` 且缺 `start_date/end_date`。
- **修正**：同步改为 `start_date`/`end_date`，删除 `created_at`。

### 🟢 A5 列表分页兼容（已正确）
- 文档为数组响应；`AcademicYear.vue` 已兼容数组与 `{results}`；mock 返回数组。✅ 无需改。

## 三、工作台（`Dashboard.vue` / `Topbar.vue` / `api/home.js` / `mock/home.js`）

文档契约（`GET /api/home/overview/`）响应：**`academic_year`(string) `current_stage`(string|null) `timeline`(array) `todos`(object)**。
- `timeline[]`：`stage_code` `display_name` `start_time` `deadline` `overdue`(bool)。

### 🔴 B1 `academic_year` 文档为字符串，被当对象
- `Dashboard.vue` 第 11 行 `overview.value?.academic_year?.name`；`Topbar.vue` 第 16 行同样；`api/home.js` 注释「返回…academic_year」。
- 文档：`academic_year` 是「当前学年名称」字符串（如 `2026-2027 学年`）。
- **修正**：改读 `overview.value?.academic_year`（直接字符串）；`mock/home.js` 的 `currentAcademicYear()` 应返回名称字符串而非 `{id,name}`。

### 🔴 B2 `current_stage` 文档为字符串，被当对象且字段名错
- `Dashboard.vue` 第 12-17 行 `overview.value?.stage?.name` / `.deadline`；`api/home.js` 注释写「当前阶段 stage」。
- 文档字段名是 `current_stage`，且为「阶段名称字符串，不在任何阶段时为 null」（无 `.name`/`.deadline` 子结构）。
- **修正**：字段改 `current_stage`，直接当字符串使用（如展示阶段名；无独立 deadline 子对象）。

### 🔴 B3 timeline 元素字段名与结构全错
- `Dashboard.vue` 第 80-97 行用 `s.name` / `s.status`(done|live|wait) / `s.start` / `s.end`。
- 文档：`display_name` `start_time` `deadline` `overdue`(bool)；**无 `status` 枚举**，是否「进行中」需由时间/`overdue` 自行推导。
- **修正**：改读 `display_name`/`start_time`/`deadline`/`overdue`；状态标签（已结束/进行中/未开始）前端用 `overdue`+当前时间与 `start_time`/`deadline` 比较得出。

### 🟡 B4 `todos` 结构文档未定义
- 前端 `todosCount = overview.value?.todos?.count`（`Dashboard.vue` 第 19 行）。
- 文档仅写 `todos: object`；`backend-interface-analysis.md` 明确其后端固定 `{count:0}`（功能未实现）。
- **修正**：`count` 形态与已知后端一致，可保留；但属文档未正式定义字段，建议只作空态展示、不强耦合内部结构（且页面已按空态处理，符合现状）。

### 🟢 B5 Mock 时间轴/阶段结构非文档
- `mock/home.js` 返回 `stage:{name,deadline,status}`、`timeline[].{name,start,end,status}` 全部为非文档结构。
- **修正**：随 B1/B2/B3 一并改。

## 四、操作日志（`OperationLog.vue` / `api/audit.js` / `mock/audit.js`）

文档契约（`GET /api/operation-logs/` 及 `/{id}/`）字段：**`id` `operator_name` `operation_type`(enum) `target_type` `target_id` `before_data`(object) `after_data`(object) `ip_address` `created_at`**；分页 `{count,next,previous,results}`。
- `operation_type` 枚举（大写）：`CREATE/UPDATE/DELETE/REVIEW/IMPORT/EXPORT/LOGIN/SELECTION`。

### 🔴 C1 字段名全错
- `OperationLog.vue` 使用 `log.operator` `log.operator_username` `log.action` `log.detail` `log.ip` `log.log_no` `log.user_agent`。
- 文档对应为 `operator_name` / `operation_type` / `ip_address`；且**无** `operator_username`/`detail`/`log_no`/`user_agent`。
- **修正**：改用 `operator_name`、`operation_type`、`ip_address`；「详情」列应展示 `before_data`/`after_data`（JSON 快照），去掉 `detail` 列。

### 🔴 C2 `operation_type` 枚举取值/大小写错误
- `OperationLog.vue` 的 `ACTION_META` 与筛选用 `login/logout/create/update/delete/import`（小写），且含文档**不存在**的 `logout`，缺 `REVIEW/EXPORT/SELECTION`。
- 文档枚举为大写 `CREATE/UPDATE/DELETE/REVIEW/IMPORT/EXPORT/LOGIN/SELECTION`。
- **修正**：枚举键改大写；筛选选项与映射对齐文档（保留 LOGIN，去掉 logout，补 REVIEW/EXPORT/SELECTION）。

### 🟡 C3 列表筛选 query 参数文档未列出
- `api/audit.js` 及 `OperationLog.vue` 发送 `operator/action/date_from/date_to/search/page`；文档 `GET /api/operation-logs/` 写「无」参数。
- **修正**：标注为前端假设，联调时以真实后端为准；若后端不支持则移除筛选（先按文档保留列表即可）。

### 🟡 C4 Mock 字段全为非文档
- `mock/audit.js` 用 `operator/operator_username/action/detail/ip/user_agent/log_no`，`actions` 含 `logout`。
- **修正**：随 C1/C2 改；`actions` 枚举改大写并去掉 logout。

### 🟢 C5 分页结构正确 ✅
- `mock/audit.js` 返回 `{count,next,previous,results}`，与文档一致。

## 五、师生批量导入（`ImportUsers.vue` / `api/import.js` / `ErrorDetailModal.vue` / `mock/import.js`）

文档契约：
- `GET /api/imports/{id}/errors/` → **数组** `[{ row_no, field_name, raw_value, error_message }]`。
- `POST /api/imports/students/commit/` 响应 `{ batch_id, success_rows }`；`POST /api/imports/teachers/commit/` 响应 `{ batch_id, created, updated }`。
- `GET /api/imports/{id}/` 字段：`id` `import_type`(enum TEACHER/STUDENT) `status`(enum) `total_rows` `success_rows` `failed_rows` `created_at`。

### 🔴 D1 错误明细响应被当 `{errors:[...]}`，实际是数组
- `ImportUsers.vue` 第 63 行 `batchErrors.value?.errors || []`；`mock/import.js` 第 117 行返回 `{ errors: [...] }`。
- 文档该接口直接返回数组。
- **修正**：前端改 `batchErrors.value || []`；mock 直接 `return b ? b.errors : []`。

### 🔴 D2 错误项字段名全错
- 前端/Modal 用 `e.row` `e.no`(工号) `e.name`(姓名) `e.message`；Modal 列头为「行号/工号/姓名/错误信息」。
- 文档字段：`row_no`(integer) `field_name`(出错列名) `raw_value`(原始单元格值) `error_message`。
- **修正**：改读 `row_no`/`field_name`/`raw_value`/`error_message`；表格列改为「行号 / 字段 / 原始值 / 错误信息」。

### 🟡 D3 commit 响应用了不存在的 `failed_rows`
- `ImportUsers.vue` 第 69 行 `成功 ${res.success_rows} 行，失败 ${res.failed_rows} 行`。
- 文档：students/commit 仅返回 `success_rows`；teachers/commit 返回 `created`/`updated`。**两处均无 `failed_rows`**。
- **修正**：按类型分别展示——students 用 `success_rows`；teachers 用 `created`/`updated`；或统一回查批次详情（`getImportBatch`）展示 `success_rows/failed_rows`。

### 🟢 D4 批次详情 `total_rows/success_rows/failed_rows` ✅
- `ImportUsers.vue` 统计卡与文档一致。

### 🟢 D5 Mock 详情字段名 `type` 应为 `import_type`
- `mock/import.js` 用 `type`/`type_key`；文档为 `import_type`(enum)。`status`/`committed` 等文档无。
- **修正**：详情改 `import_type`；去除非文档的 `type_key`/`committed`（或仅前端演示保留但明确非文档）。

## 六、认证（`Login.vue` / `ForceChangePwd.vue` / `store/auth.js` / `api/auth.js` / `mock/auth.js`）

文档契约：`POST /api/auth/login/`→`{access,refresh,must_change_password,real_name,role_codes}`；`POST /api/auth/change-password/` 请求 `{old_password,new_password}`、响应 `{detail}`；`GET /api/auth/me/`→`{id,username,real_name,phone,user_status,role_codes}`。

### 🟡 E1 改密请求缺必填 `old_password`
- `ForceChangePwd.vue` 第 40 行仅提交 `{ new_password }`；文档 `old_password` 为必填。
- **修正**：补充「原密码」输入并一并提交。

### 🟡 E2 `me` 响应字段错
- `mock/auth.js` 的 `/api/auth/me/` 返回 `{ username, name, role_codes, must_change_password }`；文档字段为 `id` `username` `real_name` `phone` `user_status` `role_codes`。
- **修正**：`name`→`real_name`；补 `id`；去掉非文档的 `must_change_password`（store 的 mustChangePassword 已由 login 响应提供，无需 me 返回）。

### 🟢 E3 login 响应缺 `real_name`
- 文档 `real_name` 必填；`mock/auth.js` 登录未返回。前端暂未强依赖（靠 me 取姓名），但应补 `real_name` 以符合文档。

### 🟢 E4 孤儿 Mock（非文档接口）
- `mock/user.js`(`/api/user/list`)、`mock/post.js`(`/api/posts`) 对应文档**不存在**的接口，且未被任何已实现页面使用。
- **修正**：清理或移除以免误导（不属于本系统契约）。

### ✅ 符合文档
- 登录响应顶层 `access/refresh/must_change_password/role_codes` 与文档一致；`store/auth.js` 的 token 映射（access→token）与 401 跳登录逻辑正确；`request.js` 的 DRF 裸数据解包 + 错误解析（`detail`/字段错误）与文档一致。
